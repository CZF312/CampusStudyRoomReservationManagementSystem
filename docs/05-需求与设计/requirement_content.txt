1 引言

1.1 编写目的

本文档是校园自习室预约管理系统的需求分析文档，旨在明确系统的功能需求、性能需求及其他相关需求，为系统的设计、开发、测试和验收提供依据。本文档面向系统开发人员、测试人员、项目管理人员以及最终用户，是系统开发过程中的重要指导性文件。

1.2 背景

随着本校招生规模的扩大，图书馆及自习室座位资源紧张的问题日益突出。传统的自习室管理方式存在以下痛点：

- 1.占座现象严重：学生用书本、背包等物品提前占座，导致座位资源浪费，实际使用率低下；

- 2.找座困难：学生需要在多个自习室之间来回寻找空位，浪费时间且影响学习心情；

- 3.纠纷频发：因座位使用产生的矛盾和冲突时有发生，影响校园和谐；

- 4.管理困难：管理人员难以实时掌握座位使用情况，无法科学调配资源；

- 5.缺乏数据支撑：无法准确统计座位使用率、高峰时段等数据，难以进行科学决策。

为解决上述问题，本项目拟开发一套校园自习室预约管理系统，采用Spring Boot + Vue3 + MySQL技术架构，实现座位的在线预约、签到签退、信用管理等功能，提高座位资源利用效率，为学生提供便捷的学习环境预约服务。

1.3 用户特点

本系统的用户主要分为两大类：

（1）学生用户

系统的主要使用者，包括本科生、研究生等。这类用户具有一定的计算机操作基础，熟悉智能手机和网页操作，希望通过本系统方便快捷地预约自习座位。使用频率较高，尤其在期末周、考研季等高峰期。

（2）管理员用户

图书馆或自习室管理人员，负责系统的日常管理和维护以及给用户签到。这类用户需要掌握系统的各项管理功能，能够处理用户签到和反馈、调整自习室座位配置、查看统计数据等。管理员用户细分为两类：一类是超级管理员，一类是普通管理员。超级管理员拥有最高权限，可以管理所有自习室，对所有自习室均由增删查改的功能；普通管理员则只能管理自己所属的自习室。

1.4 假定与约束

（1）经费限制

（2）开发期限

系统开发周期约一个半月左右，时间较紧。

2 功能需求

2.1 系统范围

校园自习室预约管理系统是一个面向高校学生和校园自习室管理方的在线预约平台，系统开发的意图是解决近期图书馆及自习室座位资源紧张、占座纠纷频发等问题，通过信息化手段提高座位资源利用效率，为学生提供便捷的学习环境预约服务。

应用目标：

（1）为学生提供在线自习室座位预约服务，实现座位的合理分配和使用；

（2）为管理人员提供自习室管理工具，实现座位资源的科学调配；

（3）建立信用积分机制，规范学生的预约行为，减少违约现象；

（4）提供数据统计分析功能，为管理决策提供数据支撑。

作用范围：

本系统适用于高校图书馆、教学楼自习室等公共学习场所的座位预约管理。系统支持学生和管理员两种角色，学生可以进行座位预约、签到签退等操作，管理员可以进行自习室管理、座位管理、用户管理、公告发布等操作

2.2 系统功能结构

系统功能结构如上图所示，主要分为学生端功能和管理端功能两大模块。

学生端功能包括：

- 用户注册：学生通过填写个人信息和上传身份证明材料进行注册；

- （2）用户登录：学生通过学号和密码进行登录；

（3）自习室浏览：查看各自习室的位置、座位数、设施等信息；

（4）座位预约：选择日期、时间段和座位进行预约；

（5）签到签退：到达座位后向管理员出示个人二维码签到，使用完毕后自行点击签退按钮    签到；

（6）预约管理：查看和管理自己的预约记录；

（7）信用查询：查看个人信用积分和变动记录；

（8）公告查看：查看系统发布的公告和通知。

（9）学习时长统计：查看个人的日、周、月、年学习时长统计，了解个人学习情况。

（10）问题反馈：学生发现问题并将有关问题反馈到管理人员。

管理端功能包括：

（1）用户管理：管理学生用户信息，审核学生用户注册信息，查看用户信用状况；

（2）自习室管理：添加、修改、删除自习室信息；（添加、删除自习室功能仅超级管理员拥有）

（3）座位管理：管理座位信息，设置座位状态；

（4）预约管理：查看和管理所有预约记录；

（5）签到管理：管理员通过扫描学生二维码实现签到；

（6）公告管理：发布、编辑、删除系统公告；

（7）统计分析：查看座位使用率、预约统计等数据报表，并支持到处下载报表；

（8）问题反馈处理：查看学生反馈的一系列有关问题，并将相关问题工单移交有关部门。

2.3 系统总体流程

系统主要业务流程包括学生用户流程和管理员用户流程。

（1）学生用户流程

① 注册登录：学生访问系统首页，输入学号和密码进行登录，首次登录系统自动创建账号；

② 浏览自习室：查看各自习室的信息，包括位置、座位数、设施等；

③ 选择预约：选择预约日期、时间段和自习室，查看可用座位；

④ 确认预约：选择心仪的座位，确认预约信息，提交预约订单；

⑤ 签到使用：在预约时间前到达自习室，向管理员出示个人二维码，管理员扫码进行签到；

⑥ 问题反馈：学生发现座位有问题或有其它建议点击问题反馈向管理员反馈信息

⑦ 签退结束：使用完毕后，点击签退按钮完成签退；

⑧ 查看学习时长：在个人中心查看日、周、月、年学习时长统计；

⑨ 查看记录：在个人中心查看预约记录、信用积分等信息。

（2）管理员用户流程

① 登录系统：管理员使用管理员账号登录系统后台；

② 自习室管理：添加、编辑、删除自习室信息（添加、删除自习室功能仅超级管理员拥有），设置开放时间等；

③ 座位管理：管理座位布局，设置座位属性（是否有电源、是否靠窗等）；

④ 用户管理：查看用户信息，处理违规用户，管理黑名单；

⑤ 预约管理：查看所有预约记录，处理异常情况；

⑥ 签到管理：用于查看用户签到情况

⑦ 公告管理：发布系统公告，通知学生相关事项；

⑧ 统计分析：查看座位使用率、预约统计等报表，为决策提供依据；

⑨ 问题反馈处理：收到学生的反馈，查看问题以便解决改善；

2.4.3.5 信用积分规则

为规范学生的预约行为，减少违约现象，系统建立信用积分机制。具体规则如下：

（1）初始积分：新用户注册后初始信用积分为300分；

（2）违约扣分：未签到扣50分；超时签退扣50分；

（3）签到奖励：在预约开始前15分钟至开始后15分钟内签到视为准时签到，每次准时签到奖励5分；

（4）积分上限：信用积分最高为5 00分，不超出上限；

（5）黑名单规则：信用积分减至0或以下时，自动进入黑名单，禁止预约功能；黑名单期限为7天，7天后自动解除，信用积分恢复为1 0分。

2.4.5 学习时长统计（学生用户）

2.4.5.1 功能描述

学生用户可以在个人中心查看个人的学习时长统计，包括日报、周报、月报和年报。系统根据用户的签到签退记录自动计算实际学习时长，帮助学生了解自己的学习情况，合理规划学习时间。

2.4.5.2 业务建模

2.4.5.3 用例描述

| 描述对象 | 描述内容 |
|---|---|
| 标识符 | UC-Durationstatics |
| 用例名称 | 学习时长统计 |
| 参与者 | 本校本科生、研究生用户 |
| 前置条件 | 用户已登录，有签到签退记录 |
| 后置条件 | 查看个人学习时长统计数据 |
| 基本流程 | 1. 进入个人中心 2. 点击"学习时长统计" 3. 选择统计类型（日报/周报/月报/年报） 4. 查看统计图表和数据 |
| 异常流程 | 无记录：提示暂无学习记录 |
| 业务规则 | 学习时长=签退时间-签到时间； |

2.4.5.4 用户界面

学习时长统计页面显示各类统计图表和数据，包括：（1）日报：显示当日的学习时长、预约次数、签到次数等；（2）周报：显示本周累计学习时长、日均学习时长、学习天数等；（3）月报：显示本月累计学习时长、日均学习时长、学习天数、学习趋势图等；（4）年报：显示本年累计学习时长、月均学习时长、学习天数、年度学习趋势图等。页面以折线图、柱状图等可视化方式展示学习时长变化趋势，帮助学生直观了解学习情况。

学习时长计算方法

学习时长=签退时间-签到时间其中：- 签到时间：用户点击签到按钮完成签到完成签到的时间- 签退时间：用户点击签退按钮或点击签退按钮完成签退的时间- 如果用户有多个预约时段，分别计算每个时段的实际学习时长后求和- 日报统计当日0:00-23:59的学习时长- 周报统计本周一0:00至周日23:59的学习时长- 月报统计本月1日0:00至月末23:59的学习时长- 年报统计本年1月1日0:00至12月31日23:59的学习时长

4 非功能需求

4.1 性能要求

（1）响应时间

- 页面加载时间：普通页面不超过3秒，复杂页面（如座位分布图）不超过5秒；

- 查询响应时间：简单查询不超过1秒，复杂查询不超过3秒；

- 预约操作响应时间：不超过2秒；

- 签到签退操作响应时间：不超过1秒；

- 并发处理能力：支持30-50用户同时在线操作。

（2）可用性

- 正常使用时系统稳定运行；

- 系统在开发测试期间正常运行；

- 计划维护时间安排在凌晨2:00-4:00，需提前通知用户。

（3）数据处理能力

- 支持日活跃用户100人以上；

- 支持日预约量500笔以上；

- 数据库支持百万级数据量，查询性能不受影响；

- 数据备份：每日自动备份，保留最近30天备份。

4.2 安全保密性要求

（1）身份认证

采用学号+身份信息校验进行身份认证，确保用户身份真实可靠。

（2）数据加密

用户密码采用BCrypt加密存储；接口采用JWT令牌认证。

（3）访问控制

基于角色的权限控制，学生和管理员拥有不同的操作权限；防止越权访问。

（4）数据安全

定期备份数据，防止数据丢失；记录操作日志，便于审计和追溯。

（5）防护措施

防止SQL注入、XSS攻击等常见安全威胁；限制接口访问频率，防止恶意攻击。

4.3 灵活性要求

- 系统应支持功能扩展，便于后续增加新的功能模块；

- 界面布局应支持自适应，适配不同分辨率的设备；

- 预约规则（如预约时长、提前天数等）应可配置，便于调整；

- 信用积分规则应可配置，便于根据实际情况调整；

- 公告内容支持富文本编辑，便于发布格式化的通知。

4.4 定时任务设计

系统采用Spring框架的@Scheduled注解实现定时任务，每分钟执行一次检查，主要处理以下自动化场景：

（1）超时未签到处理：检查已过签到截止时间但未签到的预约，自动记录违约并扣除信用积分，释放座位资源；

（2）预约到期处理：检查已到结束时间但未签退的预约，自动完成签退并计算实际使用时长；

（3）黑名单自动解除：检查黑名单到期用户，自动解除预约限制并恢复信用积分。

4.5 异常处理

（1）信用积分不足：当用户信用积分为0时，禁止预约功能，仅可查看已有预约记录和个人信息；

（2）自习室关闭：当管理员关闭某自习室时，系统自动取消该自习室所有未开始的预约，并通过站内通知用户，取消不扣除信用积分；

（3）座位故障：当座位状态被管理员设为维修或停用时，系统自动取消该座位所有未开始的预约并通知用户；

（4）并发冲突：当多个用户同时预约同一座位时，系统采用数据库乐观锁机制，保证同一座位同一时段仅被一个用户预约成功。
