## 一、本次实施目标回顾

本次变更以「第三版需求文档数据字典」为硬约束，对整个系统（后端运行时初始化、SQL 快照、前端展示、测试夹具）进行了一次系统性的规范化落地。核心原则：

1. **枚举值直接在数据库中存中文**，不再存英文代码
2. **信用分统一采用 0-500 口径**
3. **数据库规范化**：拆多值字段、删物理派生字段、补外键约束
4. **数据清洗**：学号 12 位、年级 4 位、预约号 16 位、房间/座位编号 ≤10 字符
5. **前后端一致性**：后端、SQL 快照、前端展示三方对齐

## 二、已完成的工作

### 2.1 后端核心（4 个 Java 文件）

#### `AppService.java` — 核心业务逻辑

| 改动项 | 旧值 | 新值 |
|--------|------|------|
| 枚举常量语言 | `ROLE_STUDENT = "STUDENT"` | `ROLE_STUDENT_DB = "学生"` |
| 预约状态 | `PENDING / USING / COMPLETED` | `RES_PENDING = "待使用"` 等中文语义常量 |
| 管理员角色 | `SUPER_ADMIN / ADMIN` | `ROLE_SUPER_ADMIN_DB = "超级管理员"` 等 |
| 账号状态 | `NORMAL / DISABLED` | `ACCOUNT_NORMAL = "正常"` 等 |
| 座位状态 | `NORMAL / DAMAGED / DISABLED` | `SEAT_NORMAL = "空闲"` 等 |
| 信用分上限 | `CREDIT_SCORE_MAX = 300` | `CREDIT_SCORE_MAX = 500` |
| 自动签退条件 | MySQL `timestamp()` | Java `LocalDateTime.now()` 判断（跨数据库兼容） |
| 业务判断函数 | `statusIs(status, "PENDING")` | `statusIs(status, RES_PENDING, "PENDING")` 双向兼容 |
| 派生字段计算 | `study_room.seat_count` 物理列 | 动态 SQL：`select count(*) ... as seat_count` |
| 房间查询派生列 | `cell_count` 物理列 | 动态 SQL：`row_count * col_count as cell_count` |
| 按学号签到逻辑 | 按 `reserve_date desc` 选最近预约 | 优先选「当前处于签到窗口」的待使用预约 |

#### `DatabaseInitializer.java` — 运行时建表与数据初始化

| 改动项 | 说明 |
|--------|------|
| 新增设施拆分表 | `facility`、`study_room_facility` 两张表，替代 `study_room.facilities` 字符串字段 |
| 新增房间类型字段 | `study_room.room_type`（默认值 `'普通'`，取值：`普通/静音/讨论/考研专区`） |
| 外键约束补全 | 预约、签到、信用、黑名单等 24 条外键 |
| 通知类型中文化 | `'系统通知'/'使用规则'/'维护公告'/'其他'` |
| 派生字段移除 | 不再创建 `cell_count`、`seat_count`、`actual_minutes` 物理列 |
| 设施数据 | 启动时初始化：空调、WiFi、电源插座、饮水机、白板、投影设备 |
| 迁移逻辑 | `migrateThirdDictionarySchema()` 清洗旧库 |

#### `ScheduledTaskService.java` / `AppController.java`

- 定时任务改用 Java 时间判断，兼容 H2 与 MySQL
- 房间接口返回 `facilityNames` 数组，并兼容 `facilities` 拼接串

### 2.2 前端 `App.vue`
