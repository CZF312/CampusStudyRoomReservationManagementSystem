# 数据库范式与设计说明（第三版）

> **适用项目**：`<项目根目录>`  
> **对照文档**：[第三版数据字典规范化要求.md](../05-需求与设计/第三版数据字典规范化要求.md)、[数据库完整说明.md](数据库完整说明.md)  
> **范式选择结论**：在第三版需求约束下，采用 **第三范式（3NF）为主 + 适度反范式（派生字段动态计算、操作日志冗余姓名）**

---

## 1. 为什么选择 3NF 为主？

| 考量 | 说明 |
|------|------|
| 课设要求 | 需求分析第三版强调数据字典规范、外键完整、消除多值字段 |
| 业务特点 | 预约、签到、信用、黑名单之间存在稳定的一对多/多对一关系 |
| 维护成本 | 枚举中文化后，更需通过约束防止脏数据 |
| 性能 | 演示规模下 JOIN 开销可接受；热点统计用视图 `v_room_daily_usage` |

**不采用更高范式（BCNF/4NF）的原因**：设施拆表后多值依赖已消除；部分状态字段为业务枚举而非码表主键依赖，继续拆分收益有限。

---

## 2. 规范化改造对照（第三版核心）

### 2.1 消除多值字段 → 拆表（1NF/2NF）

| 原设计 | 问题 | 第三版 |
|--------|------|--------|
| `study_room.facilities` 逗号串 | 违反 1NF，无法约束、无法按设施检索 | `facility` + `study_room_facility` |

### 2.2 删除可计算派生列 → 动态查询（3NF）

| 原物理列 | 依赖关系 | 第三版 |
|----------|----------|--------|
| `study_room.seat_count` | 可由 `seat` 聚合 | `COUNT(seat.id)` |
| `study_room.cell_count` | `row_count * col_count` | 查询时计算 |
| `reservation.actual_minutes` | `sign_out - sign_in` | 查询/统计时计算 |

### 2.3 外键补全（引用完整性）

共 **24 条 FOREIGN KEY**，覆盖：

- 学生档案 → 账号
- 自习室 → 管理员
- 座位 → 自习室
- 预约 → 学生/房间/座位
- 时段片 → 预约/座位
- 签到 → 预约/学生/管理员
- 信用流水 → 学生/预约
- 反馈/公告 → 多实体关联

### 2.4 保留的适度反范式

| 项 | 原因 |
|----|------|
| `operation_log.operator_name` | 历史审计：管理员改名后仍保留当时姓名 |
| `checkin_record` 冗余 `user_id` | 加速按学生查签到，避免每次 JOIN 预约 |
| 中文枚举直接存业务表 | 第三版硬约束，不再单独码表 |

| `admin_account` | 3NF |

## 8. 数据库编程：存储过程与函数设计

为了在数据库引擎层面实现强事务保障和业务逻辑封装，系统在数据库中显式引入了如下编程对象：

### 8.1 信用积分联动存储过程 `sp_change_student_credit`
* **业务背景**：学生签到或违约时，触发多表事务修改。
* **业务逻辑**：
  1. 利用 `FOR UPDATE` 对 `student_profile` 执行排他行锁，读出旧积分。
  2. 计算新积分并约束在 `[0, 500]` 区间，更新到 `student_profile`。
  3. 写入一条 `credit_log` 积分日志流水。
  4. 如果新积分低于拉黑阈值（$\le 0$），则直接在 `blacklist_record` 自动插入拉黑记录，并将 `user_account` 账号状态更新为 `拉黑`。
* **设计目的**：将本该由 Java 执行的 5 次独立 SQL 操作，合并为在 MySQL 底层事务块（`START TRANSACTION ... COMMIT`）中的一次调用，减少网络开销并由行锁提供高并发时的强一致性保障。

### 8.2 座位预约占用检测函数 `fn_is_seat_reserved`
* **业务背景**：高效检索指定座位在特定时间片是否已经被其他学生的活动预约所占用。
* **业务逻辑**：
  - 输入参数为 `p_seat_id` 与 `p_time`，查询 `reservation_slot` 表中包含该时间点且状态为 `占用` 的记录数，返回布尔值。
* **设计目的**：封装检索逻辑，使 Java 侧和复杂报表视图可以直接使用 SQL 函数语句（如 `SELECT fn_is_seat_reserved(id, NOW())`），提高查询代码重用度。
