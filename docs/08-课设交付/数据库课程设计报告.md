## 摘要

本课程设计实现了一套面向高校场景的**校园自习室预约管理系统**，覆盖学生注册审核、座位预约、管理员签到签退、信用积分、黑名单、公告通知、反馈工单与统计分析等完整业务链路。数据库采用 **MySQL 8**，逻辑设计遵循 **第三范式（3NF）** 为主，将设施多值字段拆分为关联表，删除可计算派生列，并建立 **24 条外键约束**保证引用完整性。第三版数据字典规定业务枚举直接存储中文值，学号 12 位、预约号 16 位纯数字、信用分 0–500。系统后端基于 Spring Boot + JdbcTemplate，前端为 Vue 3 单页应用，演示数据通过 `database-full.sql` 一键导入。经自动化脚本 17 项验收与 `mvnw test` 全量测试，数据库与功能满足需求分析第三版要求。

**关键词**：自习室预约；MySQL；第三范式；外键约束；数据字典规范化

## 第 1 章 引言

### 1.1 编写目的

本报告说明「校园自习室预约管理系统」数据库设计与系统实现过程，供课程答辩、验收及后续维护使用。读者包括任课教师、项目组与验收人员。

### 1.2 项目背景

高校自习室座位紧张，传统现场占座效率低、难以追溯违约。本系统通过信息化手段实现：**在线选座预约 → 管理员签到确认 → 使用中监控 → 签退结算 → 信用积分联动**，并为管理员提供房间、座位、公告与统计管理能力。

### 1.3 用户特点


| 用户    | 特点                         |
| ----- | -------------------------- |
| 学生    | 使用学号登录，完成预约与信用查询；需先注册并通过审核 |
| 普通管理员 | 负责签到、房间/座位日常管理、反馈处理        |
| 超级管理员 | 拥有全部管理权限，含管理员账号管理          |


### 1.4 假定与约束

- 单机或局域网部署，MySQL 8 本地安装
- 浏览器访问 `http://localhost:8080`
- 第三版数据字典为数据库字段与枚举的硬约束
- 课程设计演示规模：约 50 名学生、6 间自习室、数千条预约演示数据

### 1.5 术语说明


| 术语   | 说明                                |
| ---- | --------------------------------- |
| 预约单  | `reservation` 表一条记录，含日期、时段、座位     |
| 时段片  | `reservation_slot`，按 10 分钟切片防重复占座 |
| 信用分  | 0–500，违约扣分、守约加分                   |
| 签到窗口 | 开始前 15 分钟至开始后 15 分钟可签到            |

## 第 2 章 需求分析

### 2.1 系统范围

系统分为**学生端**与**管理端**：

- **学生端**：注册登录、浏览自习室、选座预约、查看预约与信用、接收通知、提交反馈、学习统计
- **管理端**：学生审核、扫码/学号签到、房间与座位管理、公告发布、反馈处理、统计报表、操作日志

### 2.2 系统功能结构

```
【文字占位：系统功能结构图 — 树形图】

校园自习室预约管理系统
├── 学生子系统
│   ├── 注册与登录
│   ├── 自习室浏览与预约
│   ├── 我的预约 / 签到状态
│   ├── 信用积分与消息
│   └── 反馈与学习统计
└── 管理子系统
    ├── 签到签退
    ├── 学生与审核
    ├── 自习室 / 座位管理
    ├── 公告与通知
    ├── 反馈与黑名单
    └── 统计与操作日志
```

### 2.3 业务流程

#### 2.3.1 学生预约主流程

```
【文字占位：学生预约流程图】

注册 → 管理员审核通过 → 浏览自习室 → 选择日期时段座位
→ 提交预约（状态：待使用）→ 到馆后管理员签到（使用中）
→ 离开签退（已完成）/ 超时违约（已违约）
```

#### 2.3.2 管理员签到流程

```
【文字占位：管理员签到流程图】

管理员登录 → 签到页输入学号 → 系统匹配「签到窗口内待使用预约」
→ 写入 checkin_record → 预约变使用中 → 学生端同步
```

### 2.4 数据需求摘要（第三版）


| 数据类 | 主要约束                      |
| --- | ------------------------- |
| 学生  | 学号 12 位；年级 4 位数字；信用 0–500 |
| 预约  | 预约号 16 位纯数字；状态中文          |
| 自习室 | 房间编号 ≤10 字符；设施拆表；房间类型四类   |
| 座位  | 编号 ≤10 字符；状态中文            |
| 枚举  | 账号/预约/座位/房间等状态均存中文        |


详细字段见需求分析文档第三版第 3 章数据字典及本项目 `schema.sql`。

## 第 3 章 概念结构设计

### 3.1 实体与联系


| 实体   | 主要属性       | 联系             |
| ---- | ---------- | -------------- |
| 学生账号 | 学号、密码、状态   | 1:1 学生档案       |
| 学生档案 | 姓名、学院、信用分  | 1:N 预约         |
| 管理员  | 账号、角色      | 1:N 管理自习室      |
| 自习室  | 编号、开放时间、类型 | 1:N 座位；N:M 设施  |
| 座位   | 座位号、电源等    | 1:N 预约         |
| 预约   | 日期、时段、状态   | 1:1 签到；1:N 时段片 |
| 信用流水 | 变动值、原因     | N:1 学生         |


### 3.2 E-R 图

```
【文字占位：总 E-R 图 — 建议绘制】

实体矩形：user_account, student_profile, admin_account, study_room,
          facility, seat, reservation, checkin_record, credit_log

联系菱形：
  - 学生「拥有」档案（1:1）
  - 自习室「包含」座位（1:N）
  - 自习室「配备」设施（M:N，经 study_room_facility）
  - 学生「发起」预约（1:N）
  - 预约「占用」座位（N:1）
  - 预约「对应」签到（1:1）
```

### 3.3 概念设计说明

- 原 `facilities` 逗号字段在概念层拆为**设施实体**与**配备联系**
- 原 `temp_leave`（暂离）在第三版需求中移除，不纳入概念模型
- 可计算属性（座位数、格子数、实际时长）不作为实体属性，留待逻辑/查询层处理

## 第 4 章 逻辑结构设计

### 4.1 关系模式

第三版共 **16 个关系模式**（表）：

1. `user_account(id, username, password_hash, role, status, …)`
2. `student_profile(id, user_id→user_account, student_no, name, grade, credit_score, …)`
3. `admin_account(id, account, role, status, …)`
4. `study_room(id, room_code, room_type, manager_id→admin_account, row_count, col_count, …)`
5. `facility(id, name)`
6. `study_room_facility(room_id→study_room, facility_id→facility)` — 联合主键
7. `seat(id, room_id→study_room, seat_no, status, has_power, …)`
8. `reservation(id, reservation_no, user_id, room_id, seat_id, status, …)`
9. `reservation_slot(id, reservation_id, seat_id, slot_start, slot_end)`
10. `checkin_record(id, reservation_id, user_id, admin_id, …)`
11. `credit_log(id, user_id, reservation_id, change_value, …)`
12. `blacklist_record(id, user_id, status, …)`
13. `announcement(…)`、`notification_message(…)`、`feedback_ticket(…)`、`operation_log(…)`

### 4.2 范式分析


| 改造              | 范式依据              |
| --------------- | ----------------- |
| 设施拆表            | 消除多值属性，满足 1NF/2NF |
| 删除 seat_count 等 | 消除传递/可计算依赖，满足 3NF |
| 外键约束            | 保证参照完整性           |


详见 [数据库范式与设计说明.md](../06-部署配置/数据库范式与设计说明.md)。

### 4.3 完整性约束


| 类型    | 示例                           |
| ----- | ---------------------------- |
| 实体完整性 | 各表主键 `id` 自增                 |
| 参照完整性 | 24 条 FOREIGN KEY             |
| 用户定义  | 学号长度、信用范围、唯一预约号              |
| 业务规则  | 同座位同时段 `reservation_slot` 唯一 |

## 第 6 章 系统功能实现

### 6.1 总体架构

```
【文字占位：系统三层架构图】

浏览器 (Vue 3 SPA)
    ↓ HTTP / REST JSON
Spring Boot 3.5 (Controller → AppService → JdbcTemplate)
    ↓ JDBC
MySQL 8 (study_room_reservation)
    ↑
磁盘 uploads/（材料 PDF、布局 PNG）
```

### 6.2 技术选型


| 层次   | 技术                                  |
| ---- | ----------------------------------- |
| 前端   | Vue 3 + Vite；状态归一化 `canonical()`    |
| 后端   | Spring Boot 3.5、Spring Security、JWT |
| 数据访问 | JdbcTemplate（无 JPA）                 |
| 数据库  | MySQL 8；测试 H2                       |
| 构建   | Maven、npm                           |


### 6.3 核心模块实现

#### 6.3.1 预约与防冲突

- 创建预约时写入 `reservation` 及多条 `reservation_slot`
- 唯一约束 `(seat_id, slot_start)` 防止同座同时段重复预约

#### 6.3.2 签到方式

- `AppService` 优先查询当前处于签到窗口的「待使用」预约
- 管理员通过 `POST /api/admin/checkin/student-no` 传入 `studentNo` 完成签到（V3.0 移除二维码，改为学号签到）

#### 6.3.3 信用积分

- 上限 500；取消/违约按规则写入 `credit_log`
- 联动 `student_profile.credit_score`

#### 6.3.4 设施展示

- 查询 JOIN `study_room_facility` + `facility`
- 接口返回 `facilityNames[]` 与 `facilities` 拼接串

#### 6.3.5 定时任务

- 超时未签到自动违约、使用中自动签退
- 使用 `LocalDateTime.now()` 保证 H2/MySQL 一致

### 6.4 界面实现


| 端   | 主要页面                     |
| --- | ------------------------ |
| 学生  | 登录、自习室列表、选座、我的预约、信用、个人中心 |
| 管理  | 签到、学生审核、房间/座位、统计、反馈、公告   |

## 第 8 章 总结与展望

### 8.1 工作总结

本课程设计完成了从需求分析、概念/逻辑/物理设计到系统实现与测试的完整闭环。第三版数据字典规范化使数据库结构更清晰：设施拆表、外键完整、枚举中文化、派生字段动态化，便于课设答辩审阅与验收。一键启动脚本支持清空本地库后导入标准快照，保证演示数据一致。

### 8.2 不足与展望


| 项    | 说明                          |
| ---- | --------------------------- |
| 并发性能 | 未做大规模压测，可考虑 Redis 分布式锁      |
| 暂离功能 | 第三版已移除 temp_leave，若需求变更可再设计 |
| 报表   | 可增加更多维度的 OLAP 分析            |
| 移动端  | 当前为响应式 Web，可扩展小程序           |
