02 / Background & Objectives

项目背景与系统定位

  • 高校自习室“占座”痛点
    传统高校自习室恶意占座高发，导致有限的空间资源严重浪费。
  • 信用追踪体系缺失
    缺乏对爽约、早退等行为的自动化数据追踪，学生守约惩戒难落实。
  • 数据化决策支撑
    为管理层提供座位使用率分析、高峰段热度等动态报表辅助运营。

04 / System Architecture

系统架构与持久层技术选型

  • 前后端分离 SPA 模式
    Vue 3 + Element Plus + Spring Boot 3.5 + Spring Security + JWT 鉴权保护。
  • 持久层决策：JdbcTemplate 替代 ORM
    弃用 JPA/Hibernate，由原生 SQL 与 JdbcTemplate 驱动，百分之百控制 SQL 执行效率，规避级联开销。
【三层技术架构图】

05 / DB Design - Normalization

数据库设计：3NF 规约与多值解耦

  • 消除多值：设施表独立
    将自习室 `facilities` 逗号多值字段拆为独立的 `facility` 表及 `study_room_facility` 关联表，防事务更新异常。
  • 消除传递依赖与冗余
    自习室移除了“座位总数”等可计算冗余字段，由 Seat 表关联动态 Count，实现第三范式。

06 / DB Design - Conflict Prevention

高精度防冲突：离散时间片设计

  • 区间判断在高并发下的死锁痛点
    在预约主表上直接对时间区间 `Overlaps` 进行并发检查极难在行锁中得到保证。
  • 30分钟时间片打散：唯一性规约
    预订 9:00-11:00 会打碎为 4 个离散 `reservation_slot` 单元，在此表建立 `(seat_id, slot_start, status)` 联合唯一物理索引。

07 / Backend Service Engine

后端核心控制与定时调度服务

  • 资格链式校验
    实名正常状态校验 ➔ 信用分核算限制 ➔ 每日预约次数限制 ➔ 细粒度冲突锁表。
  • ScheduledTaskService 每分钟自动流转
    15分钟未到扣信用50分并冻结黑名单 ➜ 到期自动签退释放座位 ➜ 黑名单过期解冻恢复信用。
